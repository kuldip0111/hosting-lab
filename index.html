1. What is hosting?

Hosting means making your website's files available from a computer connected to the internet.

💻

Your code

HTML creates structure, CSS creates appearance, and JavaScript adds behavior. On a static site, the browser can use these files directly.

🗄️

Web server

A server stores your files and responds to HTTP/HTTPS requests when someone asks for your website.

🌐

Domain

A domain such as example.com is a human-friendly name. DNS connects that name to the infrastructure serving your site.

2. What happens when someone opens your site?

Follow one request from the browser to your HTML.

1

Browser

User enters example.com.

2

DNS

Domain is resolved to the hosting destination.

3

HTTPS

Browser establishes a secure connection.

4

Server/CDN

Hosting infrastructure finds your files.

5

Browser

HTML, CSS and JS are downloaded and rendered.

3. Static vs dynamic websites

This file is a static website.

📄 Static

Pre-created files: HTML, CSS, JS, images. Great for portfolios, documentation, landing pages and learning projects.

⚙️ Dynamic

A server executes application code and may talk to a database. Examples include many e-commerce and CMS applications.

🔌 API-backed

The frontend can still be static while JavaScript calls APIs hosted elsewhere for login, data, payments, search, etc.

7. Git deployment commands

  
A common workflow when your hosting provider deploys from Git.

  
# 1. Go to your project
cd my-static-site

# 2. Create a Git repository
git init

# 3. Save your files
git add .
git commit -m "Initial static site"

# 4. Connect your GitHub repository
git remote add origin https://github.com/YOUR_USERNAME/my-static-site.git

# 5. Push
git branch -M main
git push -u origin main

# After future changes:
git add .
git commit -m "Update website"
git push






  
8. Important hosting concepts

  

    
DNS
DNS translates names such as my-site.com into information used to locate the service handling that domain.

    
HTTP / HTTPS
HTTP is the web protocol. HTTPS adds encryption and server identity verification using TLS.

    
CDN
A Content Delivery Network can cache and serve static assets from locations closer to visitors.

    
DNS records
A/AAAA can point a domain to IP addresses; CNAME can point a name to another hostname. Providers may require different records.

    
Build
Some sites need a build step such as npm run build. The resulting output folder is what gets deployed.

    
Cache
Browsers and CDNs may cache assets. Cache headers and versioned filenames help control when updated files are fetched.

11. Common questions

  
Can I host this exact file for free?
Yes. Many static hosting services can serve a single HTML file. Free plans and their limits vary, so check the current provider documentation before choosing one.

  
Do I need a backend for this website?
No. Everything in this page runs in your browser. A backend becomes useful when you need server-side logic, authentication, databases, private secrets, or APIs you cannot safely expose to the browser.

  
Can I put API keys inside this HTML?
Do not put private API keys or secrets in frontend JavaScript. Anything shipped to a browser should be considered visible to the user. Use a backend/serverless function for secrets.

  
What should I learn next?
Learn Git/GitHub → DNS → HTTP/HTTPS → domains → CDN/caching → CI/CD → serverless/backend deployment → Docker → cloud services.
